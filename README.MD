# Прототип браузерной RTS (часть 1)

Первая часть браузерной стратегии в реальном времени по мотивам **Age of Empires 2**.

Что уже работает:

- плоское игровое поле на координатах, центр координат `(0, 0)` в центре карты;
- карта произвольной формы и размера (задаётся списком точек);
- камера: движение клавишами, у края экрана, перетаскиванием и масштаб колёсиком;
- выбор объекта (юнита или здания) кликом;
- приказ юниту идти в точку; у каждого юнита своя скорость;
- здания — неподвижные объекты, через которые юниты не проходят.

Использованы только инструменты из курса: **Vue 3** (`ref`, `reactive`, `computed`, `defineProps`, хуки жизненного цикла), **vue-router**, **Vuex**, **TypeScript**, **SCSS**, сборщик **Vite**. Сторонних библиотек для игры нет: всё рисуется встроенным в браузер SVG.

## Запуск

```sh
cd vue-project
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно http://localhost:5173).

## Управление

| Действие | Как |
| --- | --- |
| Выбрать юнита или здание | Левая кнопка мыши |
| Снять выбор | Клик по пустому месту или `Esc` |
| Отправить выбранного юнита | Правая кнопка мыши в точку на карте |
| Двигать камеру | `W A S D`, стрелки, курсор у края окна или средняя кнопка мыши (зажать и тянуть) |
| Масштаб | Колёсико мыши |

Командовать можно только своими (синими) юнитами. Красных юнитов и любые здания можно выбрать, чтобы посмотреть информацию, но двигать их нельзя.

## Структура проекта

```
vue-project/
├── index.html                       — HTML-страница, в которую монтируется приложение
└── src/
    ├── main.ts                      — создание приложения, подключение роутера и Vuex
    ├── App.vue                      — корневой компонент, выводит текущую страницу
    ├── router/index.ts              — маршруты (пока одна страница — игра)
    ├── store/index.ts               — Vuex: id выбранного объекта
    ├── game/world.ts                — логика мира: объекты, движение, столкновения, координаты
    └── components/
        ├── pages/GamePage.vue       — страница игры: отрисовка, камера, мышь и клавиатура
        └── game/GameObjectView.vue  — отрисовка одного объекта (юнита или здания)
```

Главное разделение: **`world.ts` — это данные и правила**, а **Vue-компоненты — это отображение и управление**. В `world.ts` нет ничего от Vue, поэтому логику игры можно менять, не трогая интерфейс, и наоборот.

## Как это работает

### 1. Система координат

Все объекты живут в **мировых координатах**:

- ось X направлена вправо, ось Y — вниз (как на экране и в SVG);
- точка `(0, 0)` — центр карты, на экране она отмечена белой точкой и пунктирными осями;
- координаты могут быть отрицательными: левая часть карты имеет `x < 0`, верхняя — `y < 0`.

Мировые координаты не зависят от экрана. Где находится объект — это одно; какую часть мира мы сейчас видим — это забота камеры.

В верхней подсказке показываются мировые координаты под курсором, так легко проверить, где центр и как устроены оси.

### 2. Карта произвольной формы (`createWorld` в `world.ts`)

Граница карты — это многоугольник: массив точек `outline`, соединённых по порядку.

```ts
outline: [
  { x: -1100, y: -250 },
  { x: -700, y: -620 },
  // ...
]
```

Так карта не ограничена ни размером, ни формой: её можно сделать квадратной, вытянутой, в виде острова или гораздо больше. Для этого достаточно поменять точки — больше ничего в коде трогать не нужно.

Вспомогательные функции:

- **`boundsOf(points)`** находит прямоугольник, в который помещается вся карта (минимальные и максимальные `x` и `y`). По нему рисуется сетка и ограничивается камера.
- **`pointInPolygon(x, y, polygon)`** проверяет, лежит ли точка внутри карты. Метод «луча»: из точки мысленно проводится луч вправо и считается, сколько сторон многоугольника он пересёк. Нечётное число — точка внутри, чётное — снаружи. Это работает для любой формы, в том числе невыпуклой.

### 3. Объекты мира

Каждый объект — обычный JS-объект, созданный функцией `createObject`. У всех объектов одинаковый набор полей:

| Поле | Что значит |
| --- | --- |
| `id` | уникальный номер, по нему объект выбирается |
| `kind` | `'unit'` — юнит, `'building'` — здание |
| `name`, `label` | полное название (для панели) и короткая подпись (на карте) |
| `owner` | `'player'` — свой, `'enemy'` — противник |
| `x`, `y` | центр объекта в мировых координатах |
| `speed` | скорость юнита в единицах мира за секунду |
| `radius` | размер юнита (юнит — круг) |
| `width`, `height` | размер здания (здание — прямоугольник) |
| `moving`, `targetX`, `targetY` | идёт ли юнит и куда |

Почему одинаковые поля у юнитов и зданий: их удобно хранить в одном списке `world.objects`, искать по клику и рисовать одним компонентом. Ненужные поля просто равны 0 (у здания нулевая скорость).

Функции `unit(...)` и `building(...)` — короткие обёртки над `createObject`, чтобы стартовый мир читался как список.

**Разные характеристики.** Скорость задаётся каждому юниту отдельно, как в AoE2: крестьянин — 70, ополченец — 95, разведчик — 160. Чтобы добавить новую характеристику (здоровье, атаку, броню), достаточно добавить поле в `createObject`. Чтобы добавить новый вид объектов (дерево, золото, стену), достаточно нового значения `kind` и ветки отрисовки в `GameObjectView.vue`.

### 4. Камера

Камера — это объект `camera` в `GamePage.vue`:

```ts
const camera = reactive({ x: -160, y: -40, zoom: 1 })
```

- `x`, `y` — какая точка мира находится **в центре экрана**;
- `zoom` — масштаб: `1` — одна единица мира равна одному пикселю, `2` — двум пикселям (крупнее).

Камера показывается через атрибут **`viewBox`** у SVG. `viewBox` говорит браузеру, какой прямоугольник мира растянуть на всё окно:

```ts
const w = viewW.value / camera.zoom
const h = viewH.value / camera.zoom
viewBox = `${camera.x - w / 2} ${camera.y - h / 2} ${w} ${h}`
```

Чем больше `zoom`, тем меньший кусок мира растягивается на то же окно, то есть всё становится крупнее. Объекты при этом рисуются прямо в мировых координатах, и ни один компонент не пересчитывает положение вручную: сдвиг и масштаб делает сам браузер.

**Способы двигать камеру** (функция `moveCamera` и обработчики мыши):

1. **Клавиши `WASD` и стрелки.** Зажатые клавиши хранятся в наборе `keys` (`Set`). Пока клавиша в наборе, камера едет на каждом шаге таймера. Так движение плавное и можно зажать две клавиши сразу, чтобы ехать по диагонали.
2. **Край экрана**, как в AoE2. Если курсор ближе 16 пикселей к краю окна, камера едет в ту сторону.
3. **Средняя кнопка мыши.** Пока кнопка зажата, камера смещается в сторону, обратную движению мыши, поэтому кажется, что карта тянется за курсором.
4. **Колёсико** меняет `zoom` в пределах от 0.4 до 2.2.

Детали:

- направление делится на свою длину, поэтому по диагонали камера едет не быстрее, чем по прямой;
- шаг делится на `zoom`, поэтому на экране скорость прокрутки одинаковая при любом масштабе;
- `clampCamera` не даёт центру камеры выйти за прямоугольник карты, чтобы карту нельзя было «потерять».

### 5. Перевод экранных координат в мировые

Мышь сообщает координаты в пикселях окна, а объекты лежат в мировых. Перевод делает `screenToWorld`:

```ts
x = camera.x + (sx - viewW / 2) / camera.zoom
y = camera.y + (sy - viewH / 2) / camera.zoom
```

Центр окна соответствует точке камеры. Смещение курсора от центра окна в пикселях делится на масштаб и превращается в смещение в мировых единицах. Этой функцией пользуются клик, приказ «идти» и подсказка с координатами.

### 6. Выбор объекта

1. При нажатии левой кнопки (`onMouseDown`) запоминается точка нажатия.
2. При отпускании (`onMouseUp`) проверяется, что мышь почти не сдвинулась. Это клик, а не случайное движение.
3. Точка клика переводится в мировые координаты, и `objectAt` ищет объект под ней:
   - для юнита — расстояние до центра не больше радиуса;
   - для здания — точка внутри прямоугольника.
4. Объекты перебираются в обратном порядке отрисовки, поэтому выбирается тот, что виден сверху: юнит, стоящий у здания, выбирается раньше здания.
5. id найденного объекта (или `null`, если кликнули в пустоту) сохраняется во **Vuex** мутацией `select`.

Выбранный объект берётся из Vuex через геттер `getSelectedId` и затем ищется в мире. Он подсвечивается белой обводкой, а внизу экрана показывается панель с его названием, владельцем, скоростью и позицией.

Почему во Vuex лежит только id, а не весь объект: выбор нужен разным частям интерфейса (карте, панели, в будущем — меню команд), а координаты объектов меняются каждые 30 мс и принадлежат миру.

### 7. Перемещение юнита

**Приказ.** При нажатии правой кнопки, если выбран свой юнит, ему задаётся цель:

```ts
obj.moving = true
obj.targetX = worldPoint.x
obj.targetY = worldPoint.y
```

**Движение** выполняет `updateWorld(world, dt)` на каждом шаге игрового цикла:

1. Считается вектор от юнита до цели (`dx`, `dy`) и расстояние до неё.
2. Шаг за этот кадр равен `speed * dt`, где `dt` — сколько секунд прошло с прошлого шага. Благодаря этому скорость в единицах в секунду не зависит от частоты таймера.
3. Если до цели меньше одного шага, юнит встаёт в цель и останавливается.
4. Иначе юнит сдвигается на шаг в сторону цели: `dx / dist` и `dy / dist` дают направление длиной 1, его умножают на шаг.
5. Перед сдвигом `canStand` проверяет, что новая точка внутри карты (`pointInPolygon`) и не залезает в здание (`overlapsBuilding`). Если нельзя, юнит останавливается.

`overlapsBuilding` для каждого здания находит ближайшую к центру юнита точку прямоугольника. Если она ближе радиуса юнита, круг задевает здание.

Обхода препятствий пока нет: юнит идёт по прямой и останавливается, упёршись в здание. Поиск пути — задача следующих частей.

### 8. Игровой цикл

В `onMounted` запускается таймер (как `setInterval` на первом занятии):

```ts
timer = setInterval(tick, 30)
```

Примерно 33 раза в секунду `tick`:

1. считает `dt` — время с прошлого шага в секундах (не больше 0.1 с, чтобы после свёрнутой вкладки юниты не «телепортировались»);
2. двигает камеру (`moveCamera`);
3. двигает юнитов (`updateWorld`).

Перерисовывать вручную ничего не нужно. Мир создан через `reactive`, поэтому когда `updateWorld` меняет `x` и `y`, Vue сам обновляет нужные элементы SVG.

В `onBeforeUnmount` таймер останавливается и все обработчики `window` снимаются, чтобы при уходе со страницы ничего не работало в фоне.

### 9. Отрисовка

`GamePage.vue` рисует в одном `<svg>`:

1. **землю** — многоугольник по точкам `outline`, с толстой светлой обводкой (берег);
2. **сетку** — узор `<pattern>` с клеткой 64×64, обрезанный по форме карты через `<clipPath>`;
3. **оси** через `(0, 0)` и точку центра;
4. **пунктир** от выбранного юнита до его цели;
5. **объекты** — по одному компоненту `GameObjectView` на каждый объект.

Порядок объектов задаёт `sortForDraw`: сначала здания, потом юниты по возрастанию `y`. В SVG то, что нарисовано позже, оказывается поверх, поэтому юнит ниже на экране перекрывает юнита выше — получается простой эффект глубины.

`GameObjectView.vue` получает объект и признак выбора через `defineProps` и рисует юнита кругом, а здание прямоугольником. Цвет зависит от владельца: синий — игрок, красный — противник. У фигур стоит `pointer-events: none`: клики обрабатывает сама страница по координатам, а не отдельные SVG-элементы.

## Что дальше

Архитектура оставляет место для следующих частей:

- **новые характеристики** (здоровье, атака, броня, обзор) — новые поля в `createObject`;
- **новые виды объектов** (ресурсы, деревья, стены) — новое значение `kind` и ветка в `GameObjectView.vue`;
- **выделение рамкой и группы юнитов** — хранить во Vuex массив id вместо одного;
- **поиск пути** — заменить одну цель `targetX`/`targetY` списком точек маршрута;
- **постройка зданий и производство юнитов** — добавлять объекты в `world.objects` во время игры.
